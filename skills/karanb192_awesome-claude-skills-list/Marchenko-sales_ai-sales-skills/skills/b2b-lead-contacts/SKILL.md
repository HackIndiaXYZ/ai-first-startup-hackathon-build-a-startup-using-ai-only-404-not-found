# Глубокий поиск именных контактов (ЛПР)

Ты ищешь выходы на конкретных людей, принимающих решение о покупке продукта пользователя, у заданной компании. Это самый дорогой этап воронки: персональные ЛПР, их LinkedIn, личный Telegram, паттерн почты. Запускай прицельно — когда письма в публичный канал недостаточно и нужен именной человек, либо по прямой просьбе пользователя.

**Связь с другими скиллами.** Контекст компании (юрлицо, репутация, текущий поставщик, сигналы покупки, публичные каналы) собирает company-context. Если он ещё не запускался по этой компании — сначала запусти его: не дублируй здесь идентификацию и проверку репутации. Результат обоих скиллов → вход для скилла первого письма (cold-outreach).

**Стоп-ниши из настройки продукта:** по компаниям из стоп-списка пользователя людей не ищем — останавливаемся и сообщаем.

## Настройка под твой продукт

Возьми из файла контекста компании (`company-profile.md` в корне проекта, если есть) или спроси у пользователя перед первым запуском:

1. **Продукт:** что продаём — от этого зависит, кто в компании-цели ЛПР.
2. **Функция-владелец:** чью зону ответственности закрывает продукт (логистика, финансы, маркетинг, IT) — её руководитель и есть целевая роль после основателя.
3. **Стоп-ниши:** с кем не работаем.

## Входные данные

Название компании + URL (обязательно); контекст-досье company-context, если есть — переиспользуй его данные, не собирай заново. Несколько компаний — обрабатывай по одной, полно; больше 3 за раз — предложи разбить: это дорогой скилл, глубина важнее охвата.

**Что нужно для работы:** веб-поиск и загрузка страниц.

## Целевые роли

Определи по продукту пользователя, кто решает о такой покупке. Типовая лестница по убыванию приоритета: фаундер/CEO → COO/коммерческий директор → профильный руководитель (чью функцию закрывает продукт) → BizDev/партнёрства. У небольших компаний (<20 человек) ищи именно основателя — остальных ролей может не существовать. Спроси пользователя, если из его файла контекста роль неочевидна.

## Этап 1 — люди и их следы

- **Реестры юрлиц** (глубокая проверка, которой нет в company-context): по названию юрлица или рег. номеру из контекст-досье пробей официальные реестры юрисдикции (для РФ — rusprofile.ru, zachestnyibiznes.ru, ЕГРЮЛ; для других стран — их публичные реестры компаний). Директор и учредители из реестра — часто и есть нужный именной контакт, а заодно официальное подтверждение предварительной оценки юрлица. Юрлицо не находится — смотри реквизиты в платёжных формах и поле «Разработчик» в App Store / Google Play.
- **Telegram:** официальный канал компании (админы, закреплённые посты с контактами), бот поддержки, упоминания в отраслевых каналах ниши.
- **Статьи и интервью:** материалы ОТ ИМЕНИ компании на отраслевых площадках — авторы обычно фаундеры или маркетологи с открытыми профилями. Запросы: «[название] интервью», «[название] основатель», «[название] vc.ru» (или отраслевое медиа ниши).
- **Вакансии:** hh.ru, Habr Career, careers-страница — имена руководителей и HR, иногда прямые email.
- **LinkedIn** (обязательный блок; полные профили часто недоступны без логина — работай через поисковую выдачу):
  - Запросы: `site:linkedin.com/in "[название]"`, «[название] founder», «[название] CEO», «[название] [функция продукта]» — и латиницей, и на языке рынка. Страница компании: `site:linkedin.com/company "[название]"`.
  - По каждому найденному: ФИО, должность, прямая ссылка, признаки активности (посты, давность обновления должности).
  - Помечай, кому имеет смысл отправить connection request, и предлагай короткий повод для заявки (до 200 знаков, без питча).
  - Человек найден и в LinkedIn, и в Telegram — указывай оба канала, пользователь выберет сам.
- **Соцсети компании** по региону: Facebook/Instagram, VK — в профилях и подписях постов бывают имена.
- **Конференции и подкасты** ниши за последние 12–18 месяцев: программы выступлений называют имена и должности.
- **GitHub и документация API** — для технических компаний там бывают контакты команды.

## Этап 2 — паттерн корпоративной почты

- Собери ВСЕ подтверждённые email на домене компании. Публичные ящики из контекст-досье переиспользуй, не собирай заново. Добери из источников, которых у company-context нет: пресс-релизы, вакансии, whois, статьи, программы конференций, GitHub-коммиты, документация API.
- Определи паттерн по подтверждённым адресам, указывая источник каждого примера: ivan@domain / i.ivanov@domain / ivanov@domain / ivan.ivanov@domain.
- Паттерн ПОДТВЕРЖДЁН только при минимум двух персональных адресах одной структуры. Адреса info@, sales@, support@ паттерном не являются.
- Паттерн подтверждён и известны ФИО целевых людей — сгенерируй вероятные адреса. Учитывай транслитерацию (ivanov/ivanoff, yury/yuri, alexander/aleksandr) и сверяй с тем, как человек сам пишет своё имя латиницей (LinkedIn, GitHub, Telegram-username).
- Сгенерированные адреса помечай «гипотеза по паттерну [N подтверждений]», уверенность не выше «средняя». Никогда не выдавай сгенерированный адрес за подтверждённый.
- Несколько доменов (сайт на одном, почта на другом) — почтовый домен определяй по подтверждённым адресам, не по адресу сайта.

## Формат результата

Таблица:

| Контакт | Роль | Канал связи (подтверждён / гипотеза по паттерну / общий) | Источник (ссылка) | Дата информации | Уверенность (выс/ср/низк) |

Затем блоки: «Паттерн домена» (подтверждён/нет и чем), «Реестр» (что дала проверка юрлица, если проводилась), «LinkedIn-профили» (ссылки, кому отправить connection request и с каким поводом), «Именные контакты по каналам» (Telegram/соцсети — если все именные каналы уже видны в таблице, блок можно опустить) и финальная «Рекомендация» — с кого начинать и почему. Контекст компании не дублировать — он в досье company-context.

## Сохранение результата

Сохрани в файл `contacts_[название-транслитом]_[YYYY-MM-DD].md` — та же таблица и блоки. Одна компания = один файл. Если по компании есть контекст-досье — упомяни его имя, чтобы скилл письма взял оба файла.

## Правила честности (важнее полноты)

Выдуманный контакт стоит дороже, чем его отсутствие: рассылка по несуществующим адресам портит репутацию домена, ложное имя ЛПР направляет продажу в тупик.

- НЕ выдумывай email и телефоны. Нет прямого контакта — так и напиши и дай лучший непрямой канал.
- Каждый факт — со ссылкой; без ссылки — «не подтверждено».
- Дата у каждого источника; данные старше 18 месяцев — «устаревшие».
- Человек мог сменить компанию — проверь его последние публикации, отметь дату.
- Разделяй три уровня: подтверждённые лично / общие корпоративные / гипотезы по паттерну.
- В конце напомни пользователю: гипотезы по паттерну перед рассылкой стоит прогнать через email-верификатор (Hunter, NeverBounce и аналоги). Это опциональный платный шаг — единственный во всей библиотеке; без него гипотезные адреса используй в последнюю очередь, после подтверждённых каналов.
