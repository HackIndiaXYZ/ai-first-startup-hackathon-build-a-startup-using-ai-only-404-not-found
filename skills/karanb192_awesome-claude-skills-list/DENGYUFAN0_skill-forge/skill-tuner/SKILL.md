# Skill-Tuner · 单链路 Skill 精修器

> 思路源自 microsoft/SkillOpt，但只继承「有反馈的迭代 + 验证门控」这条骨架，砍掉外部 API、大规模评测、多轮 epoch。一次走完，全部在 Claude Code 内完成。

## 这是什么 / 何时用
- 用途：当你某天 token 额度没用完，拿来把某个**已安装的 skill**（如 elon-musk、qiushi）精修到更优状态。
- 不是基准训练：**不调用外部付费 API、不跑大规模评测、不烧额外预算**；只消耗本次 Claude Code 会话的正常额度（正好花掉当天没用完的 token）。
- 判断方式：**我出简要判断报告，最终由你人判**（保留 / 回滚 / 再调）。

## 铁律
1. **单链路一次走完**：默认只跑一遍流程，不自动多轮迭代（多轮需你明确要求）。
2. **标准由你现场口述**：评分卡来自你用大白话说出的真实感受，我不预设。
3. **外科手术式改动 + 必备份**：动手前先备份目标 SKILL.md，可一键回滚。**备份保留策略：每个 skill 只留最近一次的 `.bak`——用户判「通过」后，清掉该 skill 目录下所有更早的备份（见 Step 7）。不累积、几乎不占空间，且始终保留最近一次的回滚网。**
4. **诚实边界**：单次、小样本、我自评 → 有偏差、非客观基准分；要「可证明的 X% 提升」得上真 SkillOpt。**每次报告都要重申这一点。**

## 七步流程

### Step 0 · 锁定目标 + 读现状
- 跟用户确认要优化哪个 skill。
- 定位其 SKILL.md：先找 `~/.claude/skills/<name>/SKILL.md`；找不到再找 `~/.claude/plugins/marketplaces/**/<name>/SKILL.md`（如 qiushi 系装在 marketplace 里）。
- 完整读出当前 SKILL.md，向用户复述它现在的定位与触发方式，确认没找错。

### Step 1 · 口述评分卡
- 请用户用大白话说：「这个 skill 哪里让你不爽？你希望它更怎样？」（真实感官）
- 我把它整理成 **3–6 条可判定标准**，其中**至少 1 条负面约束 / 回归项**（例：普通聊天别乱触发、说「退出」要干净退出、首次免责声明只出一次）。
- 回读评分卡给用户确认后再继续。

### Step 2 · 组评审团 + 造测试场景
- **先组 2–3 人评审团**（人设，汲取 MiroFish 群体模拟的精华、但收敛到极小规模）：针对该 skill 选**差异最大、最能暴露问题**的虚拟用户，每个写一行「身份 + 说话风格 + 触发倾向」。
  - 默认三人设：①**目标用户**（正经按设计意图用）；②**边缘误触者**（普通聊天里措辞接近触发词、其实不想触发——专测 MANUAL-INVOKE 边界）；③**非常规用户**（诉求 / 风格偏离设计预设，测鲁棒性）。
  - **按需收敛**：触发边界敏感（手动触发类）或面向多类用户的 skill 才值 2–3 人设；纯单一场景的退化为 1 人设即可——**别为多而多**。
- 据评分卡 + 人设造 **4–6 个场景**，覆盖每条标准；**让同一意图由不同人设用各自措辞说出**，含 1–2 个**负例 / 回归例**（优先由「边缘误触者」发起）。
- 其中**留 1–2 个作「留出检查」**，改完后才拿出来跑（近似 held-out，防过拟合）。

### Step 3 · 跑基线（rollout）
- 用**当前** SKILL.md 实际跑这些场景（我按该 skill 扮演 / 执行），产出真实回答。
- 按评分卡逐条打分：pass / partial / fail + 一句理由。这是基线。
- **按人设看分布**：同一标准若只在某个人设下塌方（如「边缘误触者」被误触发），单独记下——这正是单视角 rollout 最容易漏的失分点。

### Step 4 · 反思诊断
- 找出失分根因，**定位到 SKILL.md 里具体的行 / 段**——是哪句话导致了这个问题。

### Step 5 · 最小化改动
- **先备份**：把目标 SKILL.md 复制为同目录下 `SKILL.md.bak-YYYYMMDD-HHmm`。
- 再做**最小** add / delete / replace：每处改动都对应评分卡某一条，不顺手改无关内容、不重写整篇。

### Step 6 · 门控（复跑 + 简要判断报告）
- 用**同一批场景**（含留出、**全部人设**）复跑改后的 skill，与基线逐条对比。
- **盯人设回归**：确认改动没在某个人设下引入新塌方——尤其别为修体验把触发放松、导致「边缘误触者」开始误触发。
- 产出**简要判断报告**（见下方模板），然后**停下，交给用户人判**。

### Step 7 · 收口
- 用户判**通过** → 保留新版；在 SKILL.md 末尾加一行变更日志注释（日期 + 改了什么）；把场景集存到 `<skill目录>/_tuner/scenarios.md` 以便下次回归；**清理备份（只留最近一份）**：在该 skill 目录里留下本次的 `SKILL.md.bak-*`，删掉所有**更早**的 `.bak`——每个 skill 永远只保留最近一次的回滚网，零累积。（做法：列出该目录 `SKILL.md.bak-*`，按名/时间降序留第一个、删其余。）
- 用户判**不通过** → 从 `.bak` 回滚；按用户意见可再调一轮（默认单链路只一次）。

## 简要判断报告模板
```
【Skill-Tuner 报告】目标：<skill 名>
本次评分卡（n 条）：① … ② … ③ …（标 [负例] 的为回归项）

打分对比：
  标准①  基线:partial → 改后:pass   （备注…）
  标准②  基线:fail    → 改后:pass   （备注…）
  …
回归检查：负例 / 留出 是否仍 OK：✅ / ⚠️
评审团视角：各人设是否都 OK（点名体验最差 / 会误触发的人设）：…
改了什么：逐条列（对应评分卡哪条 + 改了哪段）
我的判断：净变化一句话（值不值得留）
⛔ 边界：单次小样本 + 我自评，非客观基准分，仅供你人判参考
等你拍板：保留 / 回滚 / 再调一轮？
```

## 启动 / 退出
- 启动：`/skill-tuner`，或「启用调优模式」「优化 <某>skill」等（见 frontmatter）。激活时先一句话说明「这是单链路精修、非基准训练」，再从 Step 0 开始。
- 退出：「退出调优」「退出」「结束调优」「切回正常」→ 立即回到普通模式。
