# adversarial-gate · 压力对抗

## 什么时候调用

- 主动要求："压力对抗这个判断" / "这条是不是谄媚我" / "独立审核一下这条"。
- 你自己的写稿流程里，命题刚定稿、还没写正文之前（judgment-stress）——仅当内容类型是观点/认知/人设/价值观/思考型时触发，跟 `material-research` 的 facts/judgment 分流用同一套判断标准。
- 终稿写完、`quality-gate` 通过之后（post-draft-audit）。
- 洗稿/改写场景：判断新版本是不是真的换了骨架还是只换了皮。
- 批量产出场景：只对定位=人设/价值观/思考型的稿子跑，不需要逐条跑。

## 不要做什么（这是本 SKILL 最容易失败的地方，认真读）

- **不要把两种模式做成固定清单打勾**。不许出现"检查项 1/2/3"这种模板化的审核报告——每次的质疑点必须由 agent 现场针对这条具体内容生成，不能套用上一次审核用过的话术或问题库。如果发现自己连续几次给出的质疑角度高度雷同，这本身就是一个要警惕的信号（审核者自己也在模板化），要主动换个角度重新看这条内容。
- **不要因为判断"反共识/离经叛道/情绪强"就扣分**。压力对抗测的是论证质量（逻辑漏洞/反例/表面化/新瓶装旧酒），不是"这话讨不讨喜/立场主流不主流"。混淆这两者 = 把"敢于争辩纠错"做反成了"把锋利磨平"，是本 SKILL 的头号失败模式。
- **不要顺着已经写好的论证找理由认可它**。默认姿态是"这条大概率不够深/有漏洞"，要求稿子自己把你说服，而不是你去帮稿子找台阶。
- **不要在 judgment-stress 阶段替换判断本身**。这道闸只负责指出问题、给出质疑，命题要不要改、怎么改，是账号主自己的决定——不越权替写。
- **不要给"基本没问题""还可以再深一点"这种和稀泥的结论**。要么明确指出没扛住的具体地方，要么明确说"这条扛住了，理由是____"。
- **post-draft-audit 不要重复 quality-gate 已经查过的表达层问题**（空话/AI 腔/机械排比/书面词）——那是 quality-gate 的职责。本 SKILL 只管两件事：论证有没有真正立住、判断有没有真的被逼深。
- **Mode 2 结论为"只是包装"时不强制打回**——这条闸的角色是"逼作者看见"，不是"替他决定"。发不发是账号主的判断力问题，不是 AI 的判断力问题。
- **调用方拿到【需要调整】的结论、缺口指向"机制层"（比如"为什么会这样"没往下挖）时，调用方不许自己现编心理机制/动机去补这个缺口，必须先把缺口原样转述给账号主问清楚，禁止编几个选项让他选**。这道闸只负责指出"这里还没挖到位"，不负责提供"应该怎么挖"的答案——那个答案在账号主自己身上，不在 AI 的推测里。这条规矩来自一个真实翻车：某条判断被判需要往机制层深挖，调用方自己编了几个心理动机选项让账号主选，账号主全部否掉——这些猜测本身还隐含贬低对方的风险，不是单纯猜错这么简单。正确做法：把缺口原样问账号主，不带预设选项。

## Mode 1：judgment-stress（命题定稿后、写正文前）

### 输入

- 命题句（一句话）
- 承载命题的叙事骨架（3-5 步）
- 深化调研纪要（如有，见 `material-research` B2）
- 原始素材摘要（不需要全文，给到 agent 能理解语境的程度即可）

### 执行方式

起一个全新上下文的 agent（不共享当前对话的引导性 framing、不带当前会话已经产生的"我觉得这个判断不错"的先入为主），把上面输入连同下面的指令一起交给它：

```
你是一个苛刻但公正的怀疑读者，专门挑判断的逻辑漏洞。不是为了否定而否定，是真心觉得——一个判断
如果经不起最强的质疑，就不该拿去发表。

任务：
1. 自己生成这个判断最强的 3 个诘问/反例（不要用别人给你的清单，现场想，针对这条判断本身）。
   诘问方向可以是：逻辑链哪一步站不住、有没有真实反例、是不是只停在"现象描述"没挖到"机制/人性"层、
   这个判断是不是换了包装的老话（同类判断以前有没有人讲过，讲得比这个深）。
2. 逐条自问：这个判断在自己给的框架下，能不能扛住这个诘问？扛住了给出理由，扛不住指出具体断在哪一步。
3. 明确区分"我不同意这个立场"和"这个论证站不住"——前者不是你的工作，后者才是。反共识、情绪强烈、
   粗口自嘲，都不算问题，不许因为这些扣分。
4. 结论三选一：
   - 【扛住了】：说明为什么这三个诘问都被化解，可以进入写稿。
   - 【需要调整】：指出具体哪个环节站不住，给出这个环节该往哪个方向补（不是替写新命题，是指出
     缺口在哪、缺口的性质是什么）。**如果缺口指向"机制层没挖到"（比如"为什么会这样"没深挖），
     不要自己猜一个心理机制/动机去补——那是在替作者编答案，不是你的工作，把这个缺口原样交回去，
     由作者自己回答。**
   - 【判断本身太薄】：三个诘问都指向同一个根本问题——这个判断还没到能支撑一整条内容的深度，
     建议回材料里重新找，或者换个角度切入同一个素材。
5. 单独回答一句：这个判断是不是新瓶装旧酒——三选一【新发现】（作者自己没讲过、同类话题也少见人
   讲这么深）/【常识深化】（起点是常见说法，但往下面挖出了新层次）/【常识重述】（本质是老话换了
   场景讲，没有真正推进）。这一条独立于上面的结论——常识重述也可能"扛住了"（逻辑没漏洞），只是
   不够新，两件事不要混着判。
```

### 输出

```
## 压力对抗结果

### 诘问 1：____
自答：扛住 / 没扛住 —— ____

### 诘问 2：____
自答：____

### 诘问 3：____
自答：____

## 结论
【扛住了 / 需要调整 / 判断本身太薄】
理由：____
（如需要调整）缺口在哪、性质是什么：____

## 判断锋利度
【新发现 / 常识深化 / 常识重述】
理由：____
```

**判断锋利度**这一项单独有用处：如果你自己维护一份历史命题记录，可以把这个字段存进去，供以后纵向查——这批命题是不是在原地打转。**这一步只记录，不影响本次【扛住了/需要调整/判断本身太薄】的判定**——常识重述也可能"扛住了"（论证没漏洞），只是不够新，两件事分开看。

判定为【需要调整】或【判断本身太薄】→ 回调用方的命题环节重做，不进入下一步。**缺口如果指向"机制层没挖到"，调用方必须把缺口原话转述给账号主问清楚，禁止自己编心理机制/动机猜答案**（见上方"不要做什么"）。
判定为【扛住了】→ 记录这次的三个诘问 + 自答 + 判断锋利度，交给调用方带入后续步骤，供 Mode 2 核对是否被真正解决。

## Mode 2：post-draft-audit（终稿、quality-gate 通过后）

分两个子步骤，**只有 b 需要独立 Agent，a 是机械比对，不需要**：

### 2a. 结构查重（可选，机械比对，当前上下文直接做，不起 Agent）

如果你有自己的历史稿件记录（哪怕只是一份简单的表格：每条稿子的开头类型、骨架类型、结尾类型），这一步用来防止同一套模具反复用而不自知。跳过这一步不影响 2b 的核心价值。

做两层比对，缺一层容易漏判：

**第一层：类型标签比对**
比对本条的开头类型 / 骨架类型 /结尾类型：
- 同一类型在最近几条里出现次数明显偏高 → 标记"撞车"，具体说是哪几条撞了。
- **不是"出现过就报警"**——开头/骨架/结尾本身选项有限，正常轮换会自然重复，只有"扎堆"才是真问题。

**第二层：关键句式比对（比第一层更细，也更容易漏）**
第一层只比对标签，标签是 AI 自己写的摘要，容易用不同措辞描述实质相同的招式——如果两条稿子标签写得不一样，但摘出这三个具体位置的原句一比，会发现是同一个句法模具换了名词：**开头判断句**（立论的第一句）、**判据句**（"怎么判断/怎么看这件事有没有做到"那句，常见的是排除法结构，如"不看 A，就看 B"）、**收尾句**（最后一句落回判断的话，常见的是"跟 X 没什么关系"这类靠排除法收尾的句式）。抠掉具体名词之后，句法结构和论证动作是不是同一个 —— 是 → 命中，不管标签写得多不一样。

同一天产出的多条稿子如果命中第二层比对，风险比"隔几周偶尔重复"更高（读者大概率会前后刷到），直接标"⚠️ 扎堆"，不用等到"最近几条里出现≥3次"这种门槛才报警。

不通过不代表不能发——把撞车事实摆出来，让账号主自己决定要不要换。但命中"⚠️ 扎堆"时，不能只摆事实就算完事——必须具体指出该改哪一句、往什么方向改，不能停在"这两条有点像"这种模糊提醒。

输出：
```
## 结构查重

### 第一层：类型标签
开头类型：____ —— 最近几条里第N次出现
骨架类型：____ —— 最近几条里第N次出现
结尾类型：____ —— 最近几条里第N次出现
撞车判定：正常轮换 / ⚠️ 扎堆（具体说明）

### 第二层：关键句式
判断句：本条"____" vs 对照条"____" —— 同模具 / 不同
判据句：本条"____" vs 对照条"____" —— 同模具 / 不同
收尾句：本条"____" vs 对照条"____" —— 同模具 / 不同
撞车判定：正常轮换 / ⚠️ 扎堆（同一天产出直接标注，不套次数门槛）
若⚠️扎堆：具体建议改哪一句、往哪个方向改：____
```

### 2b. 谄媚/深度核验（独立 Agent，这是本 SKILL 的核心价值）

起一个全新上下文的 agent，交给它：终稿全文 + Mode 1 记录的命题原始版本 + 三个诘问的自答 + 深化调研纪要（如有）。指令：

```
你的任务只有一件事：判断这条终稿，是不是真的把作者一开始随手给出的判断往深处推进了，还是只是把
同一个判断用更好的现场感、更顺的句子、更漂亮的结构重新包装了一遍——实质深度没有增加。

不要用固定清单打分。做法：
1. 找到终稿里那句真正承载判断的话（可能不是标题，是文中某一句）。
2. 跟"命题定稿"阶段给的原始判断句对比：内容实质上是不是同一件事？
3. 如果实质相同，问：中间的压力对抗（三个诘问）有没有真的被写进终稿里解决掉？还是终稿绕开了那
   三个诘问，只是把判断包装得更顺口？
4. 如果发现终稿只是"包装"没有"推进"，明确指出：包装体现在哪（举具体句子），本该在哪个地方往深处
   走但没走。
5. 如果发现终稿确实把判断往深处推了（比如补上了压力对抗指出的缺口、加了机制层解释、给出了原来
   没有的具体反例回应），明确指出深在哪、是怎么深的。
6. 结论二选一：【真推进】/【只是包装】。给不出足够具体的证据支撑判断时，宁可标记为【存疑】并说明
   卡在哪，不要含糊给"基本可以"。
```

输出：
```
## 谄媚/深度核验
终稿承载判断的原句：> "____"
与命题原始判断的关系：实质相同 / 有推进

压力对抗三诘问解决情况：
- 诘问1：解决了 / 绕开了 —— ____
- 诘问2：____
- 诘问3：____

结论：【真推进】/【只是包装】/【存疑】
理由：____
```

### 2b 结论为【只是包装】时

不算硬性打回，但**必须原样呈现给账号主本人**，让他自己判断要不要改——这道闸的性质是"逼你看见"，不是"替你决定"。

## 输出格式（完整报告）

```
## adversarial-gate 报告（mode=____）

（judgment-stress 或 post-draft-audit 对应上面的输出块）

## 一句话结论
（不模棱两可：这条判断/这条终稿，站不站得住，为什么）
```

## 质检标准（元质检：这道闸自己有没有做好）

- 三个诘问是不是针对这条内容现场生成的，不是从固定题库里挑的。
- 有没有因为立场反共识/情绪强烈而误判为"有问题"。
- 谄媚核验有没有具体指出"包装体现在哪句话"，不是抽象地说"感觉包装了"。
- 结论有没有说清楚"为什么"，不是只给判定不给理由。
- 有没有跟 quality-gate 的检查项重复（空话/AI腔/书面词不归这道闸管）。

## 语言

中文。中英文之间加空格、数字与中文之间加空格。
