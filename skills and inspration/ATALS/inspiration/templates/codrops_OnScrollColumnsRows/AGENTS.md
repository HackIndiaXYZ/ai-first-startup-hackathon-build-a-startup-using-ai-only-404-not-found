# AGENTS.md

Notes for coding agents working on this repo. Read [README.md](README.md) first for what the demo is.

## Setup

- There is no build step, no package.json and nothing to install. Plain HTML, CSS and ES modules.
- Serve the root with any static server (`npx serve .` or `python3 -m http.server`). ES modules don't load from `file://`.
- GSAP 3.15.0 with ScrollTrigger, and Lenis 1.3.27, are vendored in `js/` and loaded as classic scripts before the page's module, so `gsap`, `ScrollTrigger` and `Lenis` are globals. Don't import them. Lenis' recommended CSS rules are in `css/base.css`, not a separate file.
- three.js 0.186.1 (the WebGPU build with TSL, which falls back to WebGL 2) is vendored in `js/three/` for variations 11–18, which load it through an import map in its `<head>`: `three/webgpu`, `three/tsl`, and a third entry that points `three.webgpu.min.js`'s own `./three.core.js` import at `three.core.min.js`. They're jsDelivr's minified builds with the source-map comments removed; replace all three together when upgrading.
- The font is Marlide Display Variable from Adobe Fonts (Typekit kit `rzt6nuu`, loaded in every page's `<head>`), used at weight 300 through `font-variation-settings`.
- The analytics and ad scripts are commented out in every page. They're added on the live server only; leave them commented out here.
- There are no automated tests. Check a change in a browser: scroll each page you touched from top to bottom, at desktop and at phone width (no sideways scrolling), resize mid-scroll, and turn on reduced motion (the grid should stand still and scroll natively). Keep an eye on the console. Check 11–18 on a real GPU (headless Chromium's default software renderer makes it fall back to the plain grid, on purpose), and with WebGPU unavailable (the WebGL 2 fallback).

## How a page works

```
main
  header.frame                      title, links, variations nav, tags
  .columns                          the grid: one .column per grid column
    .column                         a column of items
      figure.column__item           the ScrollTrigger trigger for that item
        .column__item-imgwrap       the frame of the picture (radius, overflow hidden)
          .column__item-img         the picture, a background image
  section.outro, p.credits
```

- The number of `.column` divs in the page is the grid's column count. It has to match `--grid-columns` for that page's `.demo-<N>` class in `css/base.css`.
- Each script maps the grid into `items` (one array per column) and `mergedItems` (all of them), each item being `{ element, column, wrapper, image }`. `column` is the item's column index, which most effects use to set per-column values.
- The effects never move what they trigger on. Triggers are the `.column__item` figures (or the `.columns` grid); the animations move the `.column`s, the wrappers and the images inside them.
- Every animation is scrubbed to the scroll (`scrub: true`), usually from `'clamp(top bottom)'` to `'clamp(bottom top)'`, with `ease: 'none'` unless the effect needs a curve.
- `.column__item-img` can be bigger than its wrapper on every side by `--grid-item-translate` (30px for `.demo-1`), so the picture can move inside its frame without showing an edge.
- Start-up, at the bottom of every script: wait for the images (`preloadImages`) and the fonts (`document.fonts.ready`), then, inside `gsap.matchMedia()` for `(prefers-reduced-motion: no-preference)`, start Lenis and call `scroll()`. Last, remove `loading` from the body, which lifts the loader.
- `initSmoothScrolling()` runs Lenis from `gsap.ticker` (with `lagSmoothing(0)`) and calls `ScrollTrigger.update()` on every Lenis scroll. It returns a function that stops it again, which `matchMedia` calls when the visitor turns reduced motion on. GSAP reverts the animations made in `scroll()` itself.

## Adding a variation

1. Copy a page with a similar grid to `index<N>.html`. Change the `demo-<N>` body class, the module script (`js/index<N>.js`), and the `.column` divs and their images if the grid differs.
2. Give it its own head: `<title>`, meta description, canonical (`https://tympanus.net/Development/OnScrollColumnsRows/index<N>.html`), `og:` and `twitter:` tags and the JSON-LD block, all with the same title, description and URL. Preload the first image the page shows. Titles and descriptions are on the ask list below.
3. Set its frame tags (`.frame__tags`) to what it uses. 01–10 use `#scroll #gsap #grid`; 11–18 add `#webgl #three.js #webgpu #tsl` (three.js's WebGPU renderer, with its WebGL fallback, and TSL). A variation that brings in something new gets its tag here and on `index.html`, which lists every tag the demo uses (the Creative Hub entry's tags come from it). Only tags that exist in WordPress (`/wp-json/wp/v2/tags?slug=…`), linked as `https://tympanus.net/codrops/hub/tag/<slug>/`; never create one, and never `shader`/`shaders`.
4. Write `js/index<N>.js` from an existing script: keep the setup (grid, items, `initSmoothScrolling`, the start-up block) and write the effect in `scroll()`. Anything that moves has to be made inside `scroll()`, so the reduced-motion revert covers it.
5. Add a `.demo-<N>` block to `css/base.css` if the grid needs different `--grid-*` values.
6. Add the number to the `.frame__demos` nav on **every** page. The current page's entry is `<span class="frame__demo frame__demo--current" aria-current="page">`, not a link. The nav holds six per row on every screen (18 is three full rows; keep the total a multiple of six if you can, so the last row isn't left short), and `css/base.css` starts each new row under 01 rather than under the label, so there's nothing to change there.
7. Update the Variations table above. The main page's description (and its JSON-LD) counts the variations ("Ten"); it's on the ask list, so check with Manoela before changing it.

## Conventions

- **Values that depend on the layout** (a size, a position, the viewport width) are functions, with `invalidateOnRefresh: true` on the ScrollTrigger, so they're measured again when the window resizes. See `js/index3.js`.
- **Off-screen pictures.** Effects push pictures past the sides of the page (variation 10 by four times a picture's width). `main` has `overflow-x: clip` so phones can't scroll sideways. Keep it `clip`: `hidden` would turn `main` into a scroll container.
- **Rows and columns by position.** `getGrid(elements)` measures the elements once and returns them with `.rows(type, merge)` and `.columns(type, merge)`, where `type` is `'even'`, `'odd'` or nothing. Call `.refresh()` on it if the layout changes before you use it.
- **WebGL (11–18), only where it's needed.** WebGL is for pictures that bend, twist or curve, which CSS can't draw, and for surfaces that must stay seamless while they fold (12): CSS 3D sorts each layer by depth as a whole, so pictures meeting at a folded joint show hairlines and flip in front of each other. Rigid moves of separate pictures (like 01–10) are CSS 3D transforms with GSAP. The DOM grid keeps the layout; `createStage()` in each page's script puts a fixed canvas over the page and draws every picture as a plane where its `.column__item` is (read with `getBoundingClientRect()` each frame), so scrolling, resizing and the frame stay the DOM's. One world unit is one CSS pixel on the z = 0 plane. The effect is in each material's `positionNode` (TSL); in 13, every row of vertices turns around the picture's vertical middle line by an angle from how far below the middle of the screen it is (none from the middle up). `cover()` frames the textures like the pictures' `background-size: cover` at `background-position: 50% 20%`. 13 positions and scales each mesh like its picture and bends it in local space; the others leave the meshes at the origin (`frustumCulled = false`) and compute every point's place in the shader from per-picture `center` and `size` uniforms, so neighbors share their edges exactly. Two pitfalls: once a material sets `positionNode`, `positionLocal` in the fragment shader is the moved point, so anything computed from a point's flat place uses `positionGeometry`; and Chrome's WebGPU shader compiler on Metal failed on swizzles of a `vec4` uniform (`rect.zw`), so the others use `vec2` uniforms. 15 and 16 light from straight in front (`LIGHT = (0, 0, 1)`), so a picture darkens the more it bends away from the viewer, down to `AMBIENT` lying on the floor; their shade is a perceived brightness, raised to 2.2 before it multiplies the colour, because the shader works in linear colour (a plain 0.3 there only looks about 60% as bright). It draws on GSAP's ticker only when the scroll or the window size changed. While it runs, `.is-webgl` on `<html>` hides the DOM pictures (they still hold their places). Without a GPU (no WebGPU or WebGL 2, or a software renderer), if loading fails, or if the GPU drops the canvas, the plain grid stays. With reduced motion the canvas is hidden and the plain grid shows.
- **Which pictures a page shows.** Slots are numbered row by row (`row × columns + column`), and slot `i` shows image `(start + i × 7) mod 72 + 1`, `start` being a different offset per page. 7 shares no factor with 72, so a page shows every image once before any repeats and neighbors, across or down, never match; it also mixes the color families.
- **Loading.** The loader stays until every grid image is decoded and the fonts are ready, so nothing pops in.

## Style

- Tabs for indentation in HTML, CSS and JS, though some blocks use spaces (most of `js/index10.js` and `js/index9.js`, the item maps in `js/index.js`, and `js/utils.js`); follow the block you're in. Single quotes and semicolons.
- Every page script is self-contained and repeats the shared setup; only `utils.js` is imported (and three.js in 11–18). Keep it that way rather than pulling the setup into a module.
- Comments are frequent: a line above most blocks saying what it is or does (`// All the columns class .column`). Per-column values come from `item.column`, through arithmetic (`(item.column+1)*2`), `if`/`else` or a `switch`. Transform origins are set through `startAt` (in a `fromTo`, in the from values instead: `fromTo` uses those as its `startAt` and ignores one passed in the to values).
- The grid is styled through `--grid-*` custom properties, overridden per `.demo-<N>`.
- No dependencies and no build tooling unless asked.
